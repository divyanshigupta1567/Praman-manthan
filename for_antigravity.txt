1. WHAT I'M BUILDING
====================================================================
I own the Flask backend that connects four teammates' ML modules
(classifier, similarity, clustering, anomaly/pressure) to the React
frontend. My job is to expose clean REST endpoints that always return
data in the shared schema below — first as realistic stub data, then
swapped for real ML outputs as teammates finish their modules. The
frontend must consume real API output only, never hardcoded numbers.

====================================================================
2. SHARED DATA SCHEMA (do not rename fields — other modules depend on these)
====================================================================

COMPLAINT object:
{
  "complaint_id": "C0001",
  "complaint_text": "string",
  "category": "Pothole | Garbage | Water Leakage | Streetlight | Sewage | Traffic Hazard",
  "predicted_category": "string",
  "confidence": 0.0,
  "latitude": 0.0,
  "longitude": 0.0,
  "locality": "Area A",
  "timestamp": "ISO 8601",
  "status": "unresolved | resolved"
}

INCIDENT CLUSTER object:
{
  "incident_id": "INC001",
  "category": "string",
  "representative_area": "Area A",
  "centroid_lat": 0.0,
  "centroid_lng": 0.0,
  "cluster_radius_km": 1.5,
  "complaint_ids": ["C0001", "C0007"],
  "complaint_count": 12,
  "similar_complaint_count": 9,
  "unresolved_count": 7,
  "first_seen": "ISO 8601",
  "last_seen": "ISO 8601"
}

INCIDENT INTELLIGENCE object (merges onto the cluster before reaching the frontend):
{
  "incident_id": "INC001",
  "baseline": 5.0,
  "current": 24,
  "z_score": 3.1,
  "spike_pct": 380.0,
  "pressure_score": 84,
  "severity": "Normal | Emerging | High Pressure",
  "auto_escalated": true
}

====================================================================
3. ENDPOINTS TO BUILD
====================================================================
GET  /api/complaints        -> list of COMPLAINT objects
GET  /api/incidents         -> list of merged INCIDENT CLUSTER + INTELLIGENCE objects
GET  /api/metrics           -> KPI summary: total_complaints, active_incidents,
                                emerging_incidents, auto_escalated_incidents
GET  /api/hotspots          -> incidents reduced to map-friendly points
                                (incident_id, centroid_lat, centroid_lng,
                                cluster_radius_km, severity)
GET  /api/trends            -> time series of complaint volume per category/locality
                                (for the trend chart)
GET  /api/briefing          -> daily operations briefing, built ONLY from computed
                                incident data — never invented or recalculated by an LLM
GET  /api/model-metrics     -> classifier evaluation metrics (accuracy, precision,
                                recall, F1) for baseline + comparison model
POST /api/complaints        -> accepts {complaint_text, latitude, longitude,
                                locality (optional)}, generates complaint_id,
                                returns it with predicted_category + confidence
